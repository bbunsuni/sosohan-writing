# Authentic Web Design

AI가 만든 것처럼 보이는 웹 UI를 피하고, 목적과 브랜드가 드러나는 인터페이스를 만드는 실무 체크리스트다. 핵심은 장식을 더하는 것이 아니라 색상·타이포그래피·간격·상태를 일관된 시스템으로 설계하는 데 있다.

## 0. 디자인 전에 수행할 일: Pre-Design

잘못된 방향으로 완성한 뒤 다시 만드는 비용이 가장 크다. 코드를 쓰거나 픽셀을 그리기 전에 아래 순서로 방향을 고정한다. 짧은 요청도 최소한 매체·톤·제약은 확인한다.

### 0-1. Discovery 폼

이미 정해진 정보는 반복해서 묻지 말고, 빠진 항목만 짧게 확인한다.

| 항목 | 확인할 질문 |
| --- | --- |
| 매체 | 랜딩페이지, 대시보드, 포스터, 슬라이드, 카드 중 무엇인가? |
| 대상 | 학생, 동료, 클라이언트, 대중 중 누가 보는가? |
| 톤 | 전문적, 친근함, 럭셔리, 발랄함, 미니멀 중 어떤 인상인가? |
| 브랜드 | parcyun studio, MDBF, 외부 브랜드, 새 컨셉 중 무엇인가? |
| 규모 | 페이지/슬라이드 수와 화면 크기는 얼마인가? |
| 제약 | 마감, 필수 색상·폰트·문구·기능은 무엇인가? |

### 0-2. 방향과 토큰 고정

브랜드가 정해졌다면 해당 브랜드 스킬로 인계한다. 브랜드가 없다면 다음 방향 중 하나를 선택하고, 선택한 뒤 팔레트와 폰트 스택을 고정한다.

- **Editorial** — 매거진, 큐레이션, 갤러리, 에세이
- **Modern Minimal** — SaaS, 대시보드, 문서
- **Tech Utility** — 개발자 도구, 데이터 표시
- **Brutalist** — 강한 인상, 실험적 화면
- **Soft Warm** — 교육, 헬스케어, 라이프스타일

이 단계가 끝나기 전에는 임의로 색상·서체·컴포넌트 스타일을 늘리지 않는다. 방향은 영감 모음이 아니라 실제 구현을 제한하는 계약이다.

### 0-3. 작성 중 Anti-AI-slop 가드레일

다음 패턴이 보이면 구현을 멈추고 목적이 있는 대체안으로 바꾼다.

- 보라색 그라디언트, 일반 이모지를 아이콘처럼 사용하기
- 왼쪽 컬러 테두리가 붙은 둥근 카드의 반복
- 큰 제목까지 Inter 하나로 처리하기
- 손으로 그린 듯한 범용 인물 SVG
- 근거 없는 지표와 숫자(예: “10배 빠름”, “98% 만족도”)
- 의미 없는 글래스모피즘과 블러

대체 원칙은 단색과 미세한 텍스처, Lucide/Heroicons 같은 일관된 라인 아이콘, 실제 데이터 또는 명시적인 placeholder, 그리고 레이어링 문제에만 쓰는 블러다.

### 0-4. 출력 전 5차원 자기 검토

최종 출력 직전에 각 항목을 1–5점으로 점검한다. 평균이 3점 미만이면 수정 후 다시 평가한다.

| 차원 | 질문 |
| --- | --- |
| 철학 | 디자인 결정마다 이유가 있고 하나의 미적 입장이 유지되는가? |
| 계층 | 가장 중요한 정보가 가장 먼저 보이는가? |
| 실행 | 간격·정렬·타이포그래피가 정확한가? |
| 기능 | 사용자가 다음 행동을 이해하고 수행할 수 있는가? |
| 절제 | 불필요한 장식과 반복을 제거했는가? |

자가 점수 자체는 결과물에 노출하지 않는다. 미달한 경우에만 수정 사실을 간단히 기록한다.

## 1. 먼저 제거할 패턴

### 색상

- 보라색/보라색 그라디언트를 기본 장식처럼 사용하지 않는다. 브랜드 색상과 온도가 맞는 뉴트럴을 사용한다.
- 시안색과 어두운 배경, 글로우 그림자를 조합하는 클리셰를 피한다. 얇은 보더와 평평한 표면이 더 안정적이다.
- 제목·수치에 그라디언트 텍스트를 쓰지 않는다. 단색으로 위계를 만든다.
- 순수 검정/흰색을 기본 배경으로 남발하지 않는다. 따뜻하거나 차가운 온도를 가진 near-black/near-white를 선택한다.
- 배경, 카드, 보더, 그림자, 보조 텍스트가 서로 다른 색 온도를 갖지 않게 한다.

### 타이포그래피

- Inter 하나만 모든 곳에 쓰지 않는다. 디스플레이용과 본문용의 역할을 구분한다.
- 한 페이지에 너무 많은 서체·굵기를 섞지 않는다. 보통 두 패밀리와 최대 세 가지 굵기로 충분하다.
- 가까운 크기의 글자를 반복하지 않는다. 단계 사이에 최소 약 1.25배의 크기 대비를 둔다.
- 본문 전체를 대문자나 모노스페이스로 처리하지 않는다. 짧은 라벨에만 제한적으로 사용한다.

### 레이아웃과 간격

- 본문은 왼쪽 정렬을 기본으로 하고, 히어로·CTA처럼 의도적인 영역만 중앙 정렬한다.
- 모든 간격을 같은 값으로 반복하지 않는다. 그룹 안은 조밀하게, 섹션 사이는 넉넉하게 둔다.
- 카드를 카드 안에 중첩하거나 모든 요소를 카드로 감싸지 않는다. 여백·타이포그래피·디바이더로 구조를 만든다.
- 텍스트 줄 길이는 대략 `65ch–70ch` 안에 둔다.
- 실제 데이터가 없는 큰 수치, 스파크라인, 장식용 통계는 넣지 않는다.
- 같은 구조의 6개 카드 그리드를 기계적으로 반복하지 않는다. 중요도에 따라 크기와 밀도를 달리한다.

### 시각 요소와 상호작용

- 글래스·블러는 장식이 아니라 실제 레이어링 문제를 해결할 때만 사용한다.
- 아이콘을 둥근 사각형 타일에 무조건 올리지 않는다. 제목 옆이나 문장 안에 자연스럽게 배치한다.
- 모든 버튼을 Primary로 만들지 않는다. 한 화면에 핵심 Primary는 하나, 나머지는 Ghost/Text로 둔다.
- 모달을 습관적으로 쓰지 않는다. 인라인 편집, 슬라이드오버, 확인 영역 등 더 가벼운 흐름을 먼저 검토한다.
- 애니메이션은 `transform`과 `opacity` 중심으로 만들고, `width`·`height`·`padding` 변경은 피한다. 바운스보다 `ease-out-quart` 또는 `ease-out-expo`처럼 절제된 easing을 사용한다.

## 2. 설계 기준

### 8pt 간격 시스템

기본 간격은 `4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96, 128px`를 사용한다. 밀도 높은 도구는 4pt 단위, 마케팅·에디토리얼은 8pt 단위를 기준으로 한다.

`내부 여백 ≤ 외부 여백`을 기본 규칙으로 삼는다. 관련 요소는 가깝게, 독립된 섹션은 충분히 떨어뜨린다. 공간은 남는 영역이 아니라 정보의 관계를 보여주는 구조다.

### 색 온도

프리미엄 UI는 완전한 무채색보다 브랜드 온도가 느껴지는 뉴트럴이 안정적이다.

- 쿨한 테크 계열: `#09090B`, `#0D0D0F`
- 앰버와 어울리는 웜 계열: `#0F0E0D`
- 기본 소프트 화이트: `#FAFAFA`
- 웜 화이트: `#F9F8F6`
- 뉴트럴 선택: Zinc는 기술적, Slate는 데이터 중심, Stone은 콘텐츠 중심

텍스트는 Primary → Secondary → Muted → Disabled 순으로 대비를 낮춘다. 배경·보더·그림자·보조 텍스트는 같은 온도 패밀리 안에서 선택한다.

### 타이포그래피

서체 크기보다 분류 대비가 먼저다. 예를 들어 기하학적 산세리프 디스플레이 + 휴머니스트 산세리프 본문, 또는 세리프 디스플레이 + 산세리프 본문 조합을 사용한다.

권장 범위:

```text
Display  48–72px   H1 32–40px   H2 24–28px   H3 18–20px
Body     15–16px   Small 13–14px Caption 11–12px
```

### 참조할 archetype

- Precision / Infrastructure: Stripe·Vercel·Linear처럼 거의 무채색에 가까운 고대비와 의도적인 microstate
- Warmth / Collaboration: Notion·Coda·Loom처럼 넉넉한 여백과 친근한 비율
- Trust / Financial: Mercury·Brex처럼 절제된 강조색과 계층화된 깊이

이 제품들의 화면을 복사하지 말고, 정보 밀도·대비·상태 설계 원리만 분석한다.

## 3. 아이콘 선택

| 환경 | 우선 선택 |
| --- | --- |
| React / Vite / Next.js | Lucide React |
| Pure HTML / CDN | Bootstrap Icons |
| 여러 아이콘 패밀리가 필요한 React | React Icons |
| Tailwind 프로젝트 | Heroicons |
| SVG 일러스트 | unDraw |

아이콘은 일관된 패밀리·선 굵기·크기를 유지한다. 이모지나 서로 다른 스타일의 아이콘을 섞어 의미 체계를 흐리지 않는다.

## 5. 구현 전·후 체크리스트

### 구현 전

1. 페이지의 목적과 핵심 행동을 한 문장으로 쓴다.
2. 화면 모드와 색 온도를 정한다.
3. 디스플레이/본문 서체, 간격 단위, 핵심 Primary 버튼을 정한다.
4. 실제 데이터와 장식용 데이터를 구분한다.

### 구현 후

1. 모바일·데스크톱에서 본문 줄 길이와 정렬을 확인한다.
2. hover, focus, active, disabled 상태를 확인한다.
3. `prefers-reduced-motion`에서 동작이 안전한지 확인한다.
4. 반복 카드, 불필요한 블러, 그라디언트 텍스트, 과도한 그림자를 제거한다.
5. 아이콘 패밀리와 접근 가능한 이름을 확인한다.

## 한 줄 원칙

좋은 인터페이스는 효과를 많이 넣은 화면이 아니라, 무엇이 중요한지 한눈에 알려 주고 각 요소가 왜 그 자리에 있는지 설명할 수 있는 화면이다.

## 다른 디자인 스킬과의 관계

이 문서는 시각 설계의 공통 기준이다. 실제 작업 순서는 `pre-design`의 Discovery → 방향 선택 → 가드레일 → 자기 검토를 먼저 실행한 뒤, 브랜드가 확정되면 `parcyun-studio` 또는 `MDBF` 스킬로 인계한다. 이후 이 문서의 구현 원칙과 체크리스트를 적용한다.
